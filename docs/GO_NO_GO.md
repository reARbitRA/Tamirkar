# اوستا: تصمیم لانچ MVP — **NO-GO**

## حکم در یک جمله

**اوستا هنوز برای لانچ عمومی آماده نیست.** اپ فعلی یک نمونهٔ نمایشی اندروید با UI فارسی، دیتابیس محلی و چند مسیر محصول است؛ اما زیرساختی که وعده‌های اصلی—پرداخت، امانت ۱۵٪، تشخیص قابل اعتماد، هویت تکنسین و شناسنامهٔ دائمی دستگاه—به آن وابسته‌اند، وجود ندارد.

## چه چیزهایی خوب است؟

- مسیرهای اولیهٔ ثبت درخواست، تشخیص، پیشنهاد تکنسین، قطعه و ضمانت در UI دیده می‌شوند.
- واحدهای پولی در مدل‌ها عمدتاً `Long` هستند، نه اعشاری.
- متن فارسی، پشتیبانی RTL و طراحی «اول تشخیص، بعد هزینه» پایهٔ مناسبی برای محصول می‌دهند.
- مسیر AI تلاش می‌کند بین چند ارائه‌دهنده جابه‌جا شود و timeout دارد.

این‌ها برای **دموی کنترل‌شده** خوب‌اند، نه برای دریافت پول از مردم.

## چرا الان نباید لانچ کنیم؟

1. **امانت ۱۵٪ واقعی نیست.** برنامه فقط عددی محلی محاسبه می‌کند؛ هیچ درگاه، webhook، دفترکل مالی، قفل پول، آزادسازی یا بازپرداخت واقعی ندارد.
2. **ورود واقعی وجود ندارد.** OTP پیش‌فرض است و اپ مستقیماً روی صفحهٔ خانه باز می‌شود. شناسه‌های کاربر و تکنسین داخل کد ثابت‌اند.
3. **کلیدهای AI نباید داخل APK باشند.** برنامه برای تماس مستقیم با ارائه‌دهندگان AI طراحی شده است. این یعنی کلید، هزینه و دادهٔ کاربر محافظت کافی ندارند.
4. **تکنسین‌ها و پیشنهادها واقعی/قابل‌اعتماد نیستند.** پیشنهادها شبیه‌سازی می‌شوند؛ KYC، تأیید صنفی، مدرک قبل/بعد و کنترل همزمانی نداریم.
5. **شناسنامهٔ دستگاه دائمی نیست.** دیتا روی گوشی است و migration مخرب می‌تواند آن را پاک کند؛ export و تاریخچهٔ غیرقابل‌دستکاری نداریم.
6. **مسیر انسانی و حقوقی نداریم.** پنل ادمین، پشتیبانی واقعی، قوانین حریم خصوصی، شرایط لغو/بازپرداخت و شرایط ضمانت منتشر نشده‌اند.

## کوتاه‌ترین مسیر تا MVP قابل لانچ

1. **دمو را از لانچ جدا کنید.** تا آماده شدن پول و هویت، هر build را واضحاً «demo / no payment» برچسب بزنید.
2. **یک backend کوچک ولی واقعی بسازید.** OTP، session، role، API، و کلیدهای AI فقط روی سرور باشند.
3. **فقط یک سفر کامل را درست کنید.** ثبت درخواست → پیش‌فاکتور immutable → تأیید مشتری → پرداخت sandbox → نگه‌داشت ۱۵٪ → عکس قبل/بعد → تسویهٔ دستیِ تأییدشده.
4. **دفترکل و state machine مالی بسازید.** هر پول باید یک رویداد append-only، idempotency key و قابلیت reconciliation داشته باشد.
5. **کنترل انسانی اضافه کنید.** KYC تکنسین، اپراتور اختلاف، توقف پرداخت/اعزام و کانال پشتیبانی.
6. **مدرک لانچ تولید کنید.** CI روی commit واقعی، تست E2E سفر مالی، تست ایران/3G/RTL، restore backup و runbook rollback.

## تصمیم پیشنهادی به بنیان‌گذار

- **لانچ عمومی با پرداخت: نه.**
- **دموی خصوصی بدون دریافت پول، با دادهٔ ساختگی و نظارت تیم: بله، بعد از build سبز.**
- **نسخهٔ بعدی:** بودجه و زمان را اول روی backend/auth/payment/operations بگذارید، نه افزودن قابلیت UI جدید.
